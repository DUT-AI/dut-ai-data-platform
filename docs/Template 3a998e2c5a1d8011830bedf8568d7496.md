# Template

| Heading | Nội dung |
| --- | --- |
| **Mục tiêu** | Domain giải quyết vấn đề gì, phạm vi trách nhiệm (Scope) và những gì không thuộc Domain. |
| **Thiết kế (Design)** | Kiến trúc tổng quan, nguyên tắc thiết kế và sơ đồ mô tả cách Domain hoạt động. |
| **Domain Model** | Các Entity, Value Object, Aggregate và mối quan hệ giữa chúng. Đây là phần mô hình nghiệp vụ của Domain. |
| **Internal Data Model** | Cấu trúc dữ liệu chuẩn (Internal Schema) mà Domain sử dụng để biểu diễn dữ liệu. Có thể dùng Mermaid Class Diagram hoặc UML. |
| **Business Rules** | Các quy tắc nghiệp vụ bắt buộc (Invariant, Constraint, Validation Rule). |
| **Domain Service** | Các nghiệp vụ không thuộc riêng Entity nào, ví dụ Validator, Merge Service, Snapshot Builder... |
| **Infrastructure** | Các thành phần tích hợp với bên ngoài (Repository, Adapter, Storage, Queue, External API...). |
| Workflow | Mô tả luồng nghiệp vụ chính của Domain bằng Sequence Diagram hoặc Flowchart. |
| **Database Design** | Thiết kế lưu trữ (Table, Collection, Index, JSON Schema...). |
| **Quan hệ với các Domain khác** | Dependency và tương tác với các Domain còn lại trong hệ thống. |
| **Design Decisions** | Các quyết định kiến trúc quan trọng và lý do lựa chọn (Rationale). |
| **Benefits** | Ưu điểm của thiết kế. |
| **Limitations** | Hạn chế hoặc Trade-off của thiết kế. |
| **Future Extension** | Khả năng mở rộng trong tương lai mà không phá vỡ kiến trúc hiện tại. |
